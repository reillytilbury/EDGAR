# Method differences

The code reference is [EDGAR at 0943922](https://github.com/reillytilbury/EDGAR/tree/0943922dcb73b12dbee8e440b3e1ff700cb49c10). The paper reference is [Tilbury et al., bioRxiv v3](https://doi.org/10.1101/2025.11.12.688086).

| Item | Pinned implementation and baseline |
| --- | --- |
| Cell eligibility | `hypothesis_engine.main` uses strict concentration >0.55 and activity >0.4. The study plan identifies paper thresholds of ≥0.4 for both. |
| Response preprocessing | `n_pcs=0` with no spontaneous mean subtraction or z-scoring. Take the first `floor(0.4 × recording trial count)` positive-response trials per eligible cell and scale each retained response vector to L2 norm 100. |
| Cell partition | Pinned code permutes eligible cells with JAX seed 42 and splits them 50/50. The default study protocol uses that permutation with 50% discovery, 25% model selection, and the remainder locked for final evaluation. |
| Trial partition | `objective` uses JAX seed 0 and a 50/50 split within each retained trial vector. This baseline preserves preprocessing across both trial halves, including response-dependent cropping and normalization. The cell holdout therefore differs from a protocol that fits preprocessing exclusively on fitting trials. |
| Score | The pinned loss is `10 × MSE + 0.01 × number of parameters`. The run records both raw MSE and the penalized score. |
| Optimizer | The upstream objective uses Adam for up to 1,000 steps. Its `tol` argument does not drive early stopping in the active Adam loop. |
| Search | The pinned code uses eight islands, six proposals per island and `1 + exp(-i / n_iterations)` in the search loop. `edgar_study.cli run` runs that loop unchanged; the baseline invokes only the evaluator on the two fixed seeds. |
| Models | Upstream uses gemini-2.0-flash-lite (translation), gemini-2.0-flash (proposals, estimators) and gemini-2.5-flash (proposals every third generation). Phase 0 puts one OpenCode Go model in all three roles. Free run: `hy4-flash-free`. Planned paid run: `deepseek-v4.1-flash`, with `muse-spark-1.3-contributor` reading images only. The tier switch every third generation is a no-op when all tiers use the same model. |
| Prompts | Upstream picks the prompt family from the model name's first letter (`g` Gemini, `c` Claude). The runner always passes `llm_type='g'`, the Gemini prompts used for the paper. |
| Generation settings | Upstream sends Gemini temperatures of 1 + exp(−i/N) ∈ (1, 2], and 0 for translation. At those temperatures `hy4-flash-free` degenerates into word salad, so the runner multiplies every temperature by 0.5 (`--temperature-scale`): annealing keeps its shape over (0.5, 1]. Upstream's non-thinking tiers (Gemini 2.0 Flash and Flash-Lite) map to reasoning effort `none`. Its every-third-generation thinking tier (Gemini 2.5 Flash) maps to the same model with effort `high`. With default reasoning, the free model spent all 16,000 output tokens reasoning and returned no code. Replies are capped at 32,000 output tokens. DeepSeek V4.1 Flash has no `none` effort, so the paid run will use `low` and `high`. |
| Images | Gemini read the diagnostic PNGs directly. `hy4-flash-free` and `deepseek-v4.1-flash` take PNG input, so images go straight to the proposer. With `--image-model`, a separate vision model describes each PNG in text and the proposer gets that description instead (planned for Muse Spark). |
| Requests | Upstream sends all 48 requests per step at once. The runner allows at most eight concurrent requests and retries once on a network error, 5xx, or non-quota 429. Failed requests return `None`, which upstream already counts as a failed program. |
| Final selection | Upstream picks its winner on the evaluation half (1,055 cells). `edgar_study.cli rescore` adds a strict holdout: it takes the top 10 unique learned programs by discovery loss, selects on the 527 selection cells, then scores the winner and both Gaussian seeds once on the 528 locked test cells. Upstream's own final step has already seen those locked cells, which the report discloses. |

No explicit code license file is present in the pinned upstream tree. This fork uses GitHub's native fork relationship and keeps its baseline additions separate from the original source files.
